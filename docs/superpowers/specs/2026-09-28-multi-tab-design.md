# 多标签设计：一个窗口打开多份 Markdown

**上位契约：** `SPEC.md`。本文**推翻** §1.3 的一条非目标（「多标签页」），并据此修订 §10.1、
§11.1、§11.4 的若干措辞，修订逐条列在 §9。本文未提及之处以 SPEC 为准。

**来源：** 2026-09-28 用户需求——「软件一次只能打开一个 md 文档，使用起来比较麻烦；期望参考
Windows 的 txt 编辑器那样，可以打开多个不同文档（但不必像 VSCode 一样在左侧提供文件目录栏）」。
§1 的每条决策都在同日的对话里逐条确认过。

**前置状态：** `main@dc3f489`。基线以执行时实测为准（2026-09-28：vitest 103 文件 / 2987 通过）。

---

## 1. 决策与理由

| # | 决策 | 理由 / 出处 |
|---|---|---|
| D1 | 一个窗口，顶部一排标签，**始终显示**（只开一个文件时也显示） | 用户要「像记事本」，明确不要文件树。始终显示是为了让 `+`（打开）在没有菜单栏的 Windows 上可发现——与 `f8e7961` 加模式按钮是同一个理由 |
| D2 | 打开入口 = 系统入口（Finder/资源管理器双击、打开方式、命令行与第二实例、macOS `Opened` 事件）+「打开…」对话框（⌘/Ctrl+O、标签栏 `+`、macOS File → Open…）。**不做**把文件拖进窗口 | 用户在三案中选定 |
| D3 | 模式按钮仍悬浮、可拖，默认位置下移到标签栏下方的右上角 | 用户在两案（悬浮 / 嵌进标签栏）中选定 |
| D4 | 关掉最后一个标签 = 关窗 = **退出 readit（两个平台）** | 用户选「像记事本」。tauri-runtime-wry 2.11.4 `src/lib.rs` 的 `TaoWindowEvent::Destroyed` 分支：最后一个窗口销毁即发 `ExitRequested`，不拦就退出，没有平台分支 |
| D5 | 从系统入口或对话框打开**已开着**的文件 → 切到那个标签，不重复开。文档内相对链接**始终在当前标签**跳转，即使目标已在别的标签里开着 | 元素在调用 `onNavigate` 之前就已把历史栈与 `loadedPath` 前进（`navigate.ts` 的 `go()`）。壳若改成「切到别的标签」，当前标签的元素会以为自己显示的是目标文件，此后相对链接按错的目录解析；不改元素做不到。故允许同一文件出现在两个标签，一致性交给既有的外部修改语义（§2.4） |
| D6 | ⌘/Ctrl+点击相对链接：本版**按普通点击处理**（当前标签跳转），不开新标签 | 用户选定。开新标签需要给可内嵌元素加公开回调（相对路径解析在元素内部、不公开，公开面有钉桩），推迟 |
| D7 | 每个标签独立：内容、撤销历史、滚动位置、查找、模式、保存状态、外部修改冲突、前进/后退。新标签沿用当前标签的模式；没有标签时为阅读模式 | 标签的意义所在。「沿用」延续 SPEC 现有的「模式跨文档保持」 |
| D8 | 关窗/退出时按标签顺序逐个裁决带 `●` 的标签；任何一个选「取消」，整个关闭取消 | 沿用单文档的三动作语义（SPEC §11.4），不引入「全部保存 / 全部放弃」这类新语义 |
| D9 | 每个标签宿主是**自己的滚动盒**；非当前标签保留排版、不可见、不可交互（**不用 `display:none`**） | 见 §4。这一条修正了对话中所述的「整页滚动 + 切换时记住/恢复滚动位置」 |

## 2. 用户可见行为

### 2.1 标签栏

- 固定在窗口顶部，高约 2.25rem。每个标签：文件名；有未保存修改时名字前带 `●`；后台标签有
  待裁决的外部修改冲突时带冲突标记；`×` 关闭按钮；悬停显示完整路径。
- 两个标签文件名相同时，名字后加上级目录名消歧（`README.md · docs`）；仍相同则再往上加一级。
- 点击切换；点 `×` 或鼠标中键关闭。
- 标签多了先缩窄到一个最小宽度，再横向滚动；`+` 始终可见（溢出时固定在标签栏右端）。
- 不支持拖动排序。
- 无障碍：`role="tablist"` / `role="tab"` / `aria-selected`；标签可聚焦，Enter 或空格切换。

### 2.2 打开

- 系统入口与对话框（可多选）：每个文件新开一个标签，**加在最右边**并切过去；一次打开多个时按
  顺序追加，最后一个成为当前标签。
- 已开着（规范化路径相同）→ 切到那个标签（有多个时切最左边那个），不新开。
- 对话框：只列 `.md` / `.markdown`；起始目录是当前标签文件所在目录（没有标签时由系统决定）。
- 打开失败（不存在、不是 Markdown、不是 UTF-8、读不了）：不新开标签，在通知区（§2.8）显示原因。
- 文档内相对链接：在当前标签跳转，保留前进/后退与「有未保存修改先问一句」，与现在相同。

### 2.3 切换与每个标签的状态

切换时，离开的那个标签一切保持原样（D7）。窗口标题、未保存提示条、冲突提示、模式按钮与 macOS
View 菜单的勾选、⌘/Ctrl+F 与 ⌘/Ctrl+S 的作用对象，都跟随**当前标签**。

### 2.4 保存与外部修改

- ⌘/Ctrl+S 保存当前标签。没有「全部保存」。
- 每个标签监听自己的文件。外部修改：该标签没有未保存修改 → 静默刷新（无论是否当前标签）；有 →
  冲突。当前标签的冲突立即显示「使用磁盘版本 / 保留我的修改」；后台标签的冲突先在标签上打标记，
  切过去时再显示。
- 同一文件在两个标签里（D5）：一边保存，另一边收到的就是一次外部修改，按上一条处理，不会静默覆盖。

### 2.5 关闭标签

- ⌘/Ctrl+W、`×`、中键关闭。带 `●` 的先问「保存并关闭 / 放弃并关闭 / 取消」，提示里写出文件名。
- 关掉后切到右边的标签，没有则切左边。
- 关掉的是最后一个标签 → 关窗并退出（D4）。
- 没有标签时（只会出现在不带文件启动的空状态里），⌘/Ctrl+W 直接关窗并退出。

### 2.6 关窗与退出

窗口 `×` / Alt+F4、⌘Q 与自建 Quit（SPEC §10.1 的退出保护路径不变）：按标签从左到右，对每个带
`●` 的标签，先切过去，再问「保存并关闭（退出）/ 放弃并关闭（退出）/ 取消」，提示里写出文件名；
保存失败、或保存期间又有新编辑，视为取消。全部裁决完、所有保存落定之后才放行。没有带 `●` 的标签
则直接放行。

### 2.7 快捷键与菜单

| 动作 | macOS | Windows |
|---|---|---|
| 打开… | ⌘O（File → Open…） | Ctrl+O |
| 关闭当前标签 | ⌘W（File → Close Tab，取代默认菜单的 Close Window 预定义项） | Ctrl+W |
| 下一个 / 上一个标签（首尾循环） | Ctrl+Tab / Ctrl+Shift+Tab | 同左 |
| 保存 / 切模式 / 查找 | 不变，作用于当前标签 | 不变，作用于当前标签 |

关窗口：macOS 用红色按钮；Windows 用窗口 `×` 或 Alt+F4。

### 2.8 版面

- **模式按钮**：默认位置在标签栏下方的右上角；拖动范围限制在标签栏以下；「窗口尺寸一变就回默认
  位置」不变（`dc3f489`）。
- **未保存提示条**：随之下移到标签栏以下。
- **查找栏**：不压住标签栏（§3.7）。
- **通知区**：错误提示（打开失败、保存失败等）固定显示在标签栏下方、水平居中、窗口之内，带 `×`，
  直到被关掉或被下一条替换。窄窗口下与模式按钮重叠时，通知区在上层（错误比模式切换更要紧）。
- **空状态**：只在不带文件启动时出现。提示语与「打开…」按钮在第一屏正中。

## 3. 架构

### 3.1 Rust：已开文档表

`AppState` 里的「唯一当前文档」（`current_document`、单个 `watcher`、`ResourceRoot` 的单个根）
换成一张**以 generation 为键的已开文档表**。generation 仍全局单调递增，每次成功打开分配一个新的。

| 命令 | 入参 | 出参 | 语义 |
|---|---|---|---|
| `open_document` | `path` | `{ path, source, generation }` | 规范化、校验、读 UTF-8、建 watcher、登记资源根，全部成功才登记；失败不改表 |
| `close_document` | `generation` | — | 从表中移除，释放 watcher 与资源根。未知 generation 视为已关闭，不报错 |
| `save_document` | `content, generation` | — | **不收路径**。只写表中该 generation 登记的路径；未登记（已关闭或已被替换）→ 拒绝 |
| `read_document` | `generation` | `source` | 由 `read_current_document` 改名，按 generation 查表 |
| `open_dialog` | `generation?` | — | 弹原生对话框（起始目录取该 generation 的文件所在目录），选中的路径进**既有的待打开队列**并广播 `readit-documents-pending` |
| `take_pending_path` | — | `path \| null` | 不变 |

- 保存期间持有表锁（与现在持有 `current_document` 锁同理），保存不会与打开、关闭交错。
- 标签内跳转（相对链接）：前端先 `open_document(新路径)`，成功后再 `close_document(旧 generation)`；
  失败则旧文档原样保留。

### 3.2 资源协议

URL 由 `readit://localhost/<相对路径>` 改为 **`readit://localhost/<generation>/<相对路径>`**
（Windows：`http://readit.localhost/<generation>/…`）。Rust 取首段 generation 查表得到该文档的目录，
其余解析规则（百分号解码，拒绝 `..`、盘符、绝对路径、越出目录）不变。首段不是已登记的 generation
→ 404。前端 `toReaditResourceUrl` 按标签当前的 generation 生成前缀，标签内跳转后前缀随之更新。

### 3.3 watcher 与变更事件

每个已开文档一个 `DocumentWatcher`（盯父目录、按路径过滤，与现在相同）。`readit-document-changed`
的载荷加上 `generation`；前端按 generation 分派给对应标签，去抖按标签各自进行。

### 3.4 对话框

引入 `tauri-plugin-dialog`，精确钉死。候选 `=2.8.0`（2026-09-28 时最新的 2.x；3.0 仍是 alpha，
不用）；第 1 批加入时用 `cargo tree` 确认它不抬升已钉的 `tauri =2.11.5`，抬升就改用不抬升的最高
2.x 版本，并在批次报告里写明选定的版本号。单实例插件仍须是第一个注册的插件。只从
Rust 侧调用，**不给前端授任何 dialog 权限**——`capabilities/main.json` 的精确相等棘轮不变。

### 3.5 macOS 菜单

File 菜单加 Open…（⌘O）与 Close Tab（⌘W）；默认菜单里的 Close Window 预定义项（File 与 Window
两处）移除，⌘W 只归 Close Tab。做法与已有的 Quit 替换相同：找不到要替换的预定义项就启动失败，
不静默放行。Save、View 模式项与自建 Quit 不变。

### 3.6 前端

- **`tabs.ts`（新，纯逻辑）**：标签列表与当前标签；打开时按规范化路径去重；关闭后切到哪个；
  上一个 / 下一个；重名消歧。无 DOM，单测覆盖。
- **`tab-strip.ts`（新，DOM）**：按模型渲染标签栏，只发「切换 / 关闭 / 打开」意图，不自己改状态
  （与 `mode-switch.ts` 同一模式）。
- **每个标签一套**：宿主元素（`#reader` 的子元素）、一次 `mount()`、一个 `createSaveState()`、
  资源改写（按该标签的 generation）、外部修改去抖。
- **全局一份**：组合输入门与外链拦截挂在 `#reader` 上，事件从各标签宿主冒上来，一处覆盖全部。
  查找快捷键、保存、模式切换、冲突提示条、离开提示都作用于当前标签。
- **修饰键点击**（D6）：`#reader` 上一个捕获阶段监听。⌘/Ctrl/Shift/Alt + 点击非外链：阻止默认；
  若是相对链接或 `#锚点`，改为对同一链接的一次普通点击，交给元素走当前标签跳转。外链仍归
  `external-links.ts`。
- `navigation.ts` 的 `routeDocumentOpen`（把系统入口伪装成一次链接点击）随之移除：系统入口改为开标签。

### 3.7 对可内嵌库的唯一改动

查找栏现在是 `top: 8px`（`packages/find/src/controller.ts`），固定定位时会压住标签栏。改为
`top: var(--readit-find-top, 8px)`：默认值不变，纯增量，与已有的 `--readit-find-position` 是同一类
样式钩子。壳把它设到标签栏以下。**元素与核心不动，公开导出面不变。**

## 4. 版面与滚动（D9 的理由）

对话中给出的方案是「保持整页滚动，切标签时记住 / 恢复滚动位置」。细查后改为：**每个标签宿主是
标签栏下方一块固定高度的滚动盒；非当前标签 `visibility: hidden` + `inert`，保留排版。**

1. **整页滚动时，查找命中与标题跳转会停在标签栏底下。** 查找把命中滚进视野时，文档滚动元素的可见
   带取整个视口（`find/src/controller.ts` 的 `visibleBand()`），被固定标签栏盖住的那一段也算
   「可见」，命中落在那里就不再滚。标签宿主自己滚，可见带就是宿主本身，天然在标签栏以下。
2. **滚动位置天然各自保留**，切换时不需要记录 / 恢复。`display:none` 会销毁滚动盒、滚动位置归零，
   所以非当前标签保留排版。
3. 后台标签可能在不可见时重渲染：干净的后台标签收到外部修改会静默刷新；连续打开多个文件时，前一个
   的异步水合还没完成就被切到后台。保留排版让这些渲染里的测量都发生在真实版面上。**这一条是稳健性
   考虑，不是在修已知缺陷**：曾怀疑 `display:none` 里 Mermaid 读到的行高不是 px，2026-09-28 实测
   Chromium 与 WebKit 都能正确解析（`line-height: 1.5` → `24px`），怀疑不成立。

**代价：** 窗口缩放时所有标签都要重新排版，开销随标签数线性增长。常用规模（十来个）可接受；真成问题
时再退回「`display:none` + 显式记录滚动位置」。

**副作用（行为变化，须实测）：** 分栏与源码模式下，滚动从「整页一起滚」变成「窗格 / 编辑器内部滚」。
2026-09-28 实测（真壳前端、WebKit、150 段文档、分栏）：两侧窗格与 `.cm-scroller` 的 scrollHeight
都等于 clientHeight（6051），滚轮滚的是整页（scrollY 0 → 3020）——也就是说，**元素自带的分栏滚动
同步在壳里一直没有生效**，两栏被撑成同高、跟着整页一起动。改成定高滚动盒后窗格才真正各自滚动，
同步才有机会生效；这一点须在真引擎里实测确认，不预设它一定工作。

`html, body` 不再滚动。阅读行宽规则（`#reader::part(content)`）改为作用在标签宿主上，式子不变。

## 5. 不变量

1. `save_document` 不收路径；Rust 只写表中该 generation 登记的路径；已关闭或被替换的 generation
   写不进任何文件。
2. 自写识别（按内容快照）、冲突不覆盖、组合输入门、保存串行、「保存期间又有编辑则不离开」——语义
   不变，按标签各一份。
3. 离开保护：三条原生路径（关窗、⌘Q 与自建 Quit、`ExitRequested`）仍经前端裁决；前端未 ready 时
   仍保留原生退路。`leave.rs` 的协议不改。
4. 前端不新增任何 core 权限；关掉最后一个标签后的关窗走既有的放行路径。

## 6. 具名边界（接受，不修）

- **跨文档资源显示（仅 Windows 形态）。** 一份文档若手写 `http://readit.localhost/<号>/x.png`，
  可以显示另一个已打开文档目录里的文件。只能显示：CSP 的 `connect-src` 只放行 ipc，内容出不了本机。
  macOS 的 `readit:` 形态过不了消毒（`packages/core/src/sanitize.ts`：`protocols.src` 只有
  `http`、`https`），不受影响。
- **同一文件两个标签**（D5）：一致性靠外部修改语义，不做「编辑互相同步」。

## 7. 顺带修掉的两处现有缺陷

版面重做正好覆盖它们，不单独修：

| 缺陷 | 实测（2026-09-28，真壳前端 + WebKit，视口 960×720） | 修法 |
|---|---|---|
| 不带文件启动时窗口看似空白 | 提示语在 top 864：空的 `#reader` 有 `min-height: 100vh`，把它挤出首屏 | 空状态（§2.8） |
| 保存失败等错误提示用户看不到 | 保存失败后提示在 top 8195、页高 8245，视口停在顶部：`#status` 在文档流里排在正文后面 | 通知区（§2.8） |

## 8. 测试

- **Rust 单测**：两份文档同时开着各自保存；关掉的 generation 保存与读盘被拒；资源按 generation 各自
  解析，未登记的 generation 返回 404；watcher 事件带对应 generation；对话框命令把选择送进待打开
  队列（对话框本身以接口替身测）；菜单替换守卫（找不到预定义项即失败）。
- **前端单测（happy-dom）**：标签模型（去重、关闭后切到哪个、重名消歧、上一个 / 下一个）；关窗与
  退出时逐个裁决多个带 `●` 的标签、中途取消；按 generation 分派外部修改；修饰键点击改为普通点击。
- **真引擎（Playwright，Chromium + WebKit 承重）**：把本次核实用的「真壳前端 + 桩掉 Tauri 通信」
  做成常设夹具，覆盖：开三个标签来回切、各自滚动位置保留；`●` 与冲突标记各自独立；关带 `●` 的标签
  先问；查找命中不落在标签栏下；模式按钮默认位置在标签栏下；空状态与通知区在视口内；分栏模式下

## 10. 验收线

**做完 = 以下每一句都能由用户在真机上自己复现：**

1. 在 Finder / 资源管理器里先后双击 3 个 `.md`，readit 同一个窗口里出现 3 个标签；来回切，各自的
   滚动位置不变。
2. 在标签 A 改了没保存，切到 B 再切回来，A 的修改与撤销历史都在；只有 A 带 `●`。
3. ⌘/Ctrl+O 选 2 个文件，多出 2 个标签；再选一个已经开着的文件，切到那个标签，不多开。
4. 两个标签的文档在不同目录、各自引用同名图片，两边显示的都是自己目录里的那张。
5. 关带 `●` 的标签会先问；关窗时两个带 `●` 的标签依次各问一次，选「取消」窗口不关。
6. 关掉最后一个标签，readit 退出。
7. 外部程序改了后台标签的文件：没改过的，切过去已是新内容；改过的，标签上有标记，切过去弹出冲突选择。
8. 不带文件启动，第一屏正中能看到提示和「打开…」按钮；保存失败时，错误提示出现在当前视口内。

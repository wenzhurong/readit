# Windows v0.1.2 验收缺口修复与证据纠正规格

**日期**：2026-08-29
**基线**：`main` / `61afc1510d1cc222bf53eec8ba7a6f4df623b077` / `readit-v0.1.2`
**输入证据**：`2026-08-17-windows-shell-report.md` 的 2026-08-27 追加节

## 1. 目标与边界

本轮只修复有可复现产品证据或明确工程缺口的项目，不把缺少测试环境写成代码已修：

1. 重新判定 A4 卸载残留，补上可持续运行的安装器生命周期回归。
2. 约束五处版本声明同步，避免发布包、PE 与“程序和功能”元数据漂移。
3. 补强 Windows 安装/卸载 hook 的静态断言，防止清理逻辑以后静默丢失或误删其他应用。
4. 明确记录 E2、E5、F1/F2/F3 与模式控件 UX 观察的处置边界。

不在本轮凭空修改的项目：

- F2 需要没有 WebView2 Runtime 的干净 Windows 10；当前主机不能替代。
- F3 的最终结论需要 `LongPathsEnabled=1` 且 Git `core.longpaths=true` 的深路径环境；不得改
  当前主机注册表压绿。
- E5 最终结论必须来自真实微软拼音预编辑串；合成事件只能补自动化，不能代替真机。
- 模式控件“可拖到任意绝对位置”是当前 H2 的明确契约；在没有新产品裁决前，不限制它与
  正文重叠。

## 2. A4 证据重建与修复门

### 2.1 当前事实

`installer-hooks.nsh` 已在 `NSIS_HOOK_POSTUNINSTALL` 中删除两个 `OpenWithProgids` 值和
`readit.md` ProgID；Tauri 模板本身负责删除开始菜单快捷方式与 HKCU 卸载项。2026-08-29
对原始 v0.1.2 Release 执行 `/S` 卸载，exit 0，以下项目全部消失：

- 安装目录；
- HKCU 卸载项；
- `HKCU\Software\Classes\readit.md`；
- `.md` / `.markdown` 的 `OpenWithProgids\readit.md`；
- 开始菜单和桌面快捷方式。

因此不能仅凭上一轮 UI 中间状态把根因写成“hook 缺少删除语句”。UI 路径必须从点击
`Uninstall` 一直观察到卸载进程退出，再取样。

同日完成该 UI 复核：向导进入 `Uninstallation Complete`，点击 `Close` 后窗口与卸载进程
均退出；安装目录、卸载项、ProgID、两个 OpenWith 值及开始/桌面快捷方式全部不存在。随后
重新安装同一 v0.1.2 发布包，HKCU `DisplayVersion`、主程序和卸载器 `ProductVersion` 均为
`0.1.2`。A4 据此改判通过，执行的是下述第一条分支。

### 2.2 判定分支

- **UI 完整退出后清理成功**：A4 改判通过；修复内容是测试方法、静态守卫和 CI 生命周期
  smoke，不侵入已正确工作的卸载实现。
- **UI 完整退出后仍残留**：先在 PRE/POST hook 增加 `DetailPrint`/marker 的诊断构建，定位
  是否到达 POST。只有确认 POST 未运行，才引入自定义 NSIS template 或
  `un.onUninstSuccess` 的幂等兜底。

禁止把关联删除直接搬到 `NSIS_HOOK_PREUNINSTALL`：该 hook 位于运行中应用检查之前；用户
随后取消会造成应用仍在、关联先被删掉。

### 2.3 删除边界

任何兜底都只能删除 readit 自己的内容：

- `readit.md` 值和 ProgID；
- readit 自己的卸载项；
- readit 自己的快捷方式。

不得删除整个 `.md` / `.markdown` key，不得触碰 `UserChoice`、HKLM 或其他 ProgID。

## 3. 自动化改动

### 3.1 静态 hook 守卫

扩展 `shell/test/windows-installer.test.ts`：

- 必须存在 `NSIS_HOOK_POSTUNINSTALL`；
- 必须删除两个精确的 `readit.md` OpenWith 值及 readit ProgID；
- 删除只能在 POST，不得出现在 PRE；
- 不得出现 `UserChoice`、HKLM、SHCTX 或删除整个 `.md` / `.markdown` key。

### 3.2 版本同步守卫

新增测试，要求以下五处版本完全一致：

1. `shell/src-tauri/tauri.conf.json`；
2. `shell/src-tauri/Cargo.toml`；
3. `shell/src-tauri/Cargo.lock` 中的 `readit-shell` package；
4. `shell/package.json`；
5. 根 `package-lock.json` 的 `packages.shell`。

控制面板曾显示 0.1.0 目前按“未复现/疑似旧窗口缓存”处理，不在自定义 hook 里重复写
`DisplayVersion`。人工复测必须关闭旧 appwiz 窗口并重新打开后再比较。

### 3.3 Windows Release 静默生命周期 smoke

新增 PowerShell 脚本并接入 `release-desktop.yml` 的 Windows job，在打包后执行：

1. 找到唯一 NSIS setup；
2. 静默安装到 runner 临时目录；
3. 核对 HKCU `DisplayVersion`、主程序/卸载器 PE 版本、ProgID、两个 OpenWith 值和快捷方式；
4. 静默卸载并等待进程退出；
5. 断言上述 readit 自有内容全部消失。

脚本若发现测试前已有 readit 状态应直接失败，不得清理未知用户状态后继续；安装前后还必须
断言 `.md` / `.markdown` 的 class 默认值和 `UserChoice` 未变化。失败回滚只可运行本轮注册的
readit 卸载器，或清理已确认位于 `RUNNER_TEMP` 的目录及 readit 自有值/快捷方式。Release
保持 draft；smoke 失败时禁止把该 draft 当成通过产物。它只覆盖静默路径，不替代 UI 手工门。

第二轮把“不得误删其他应用”从静态边界加强为运行时 sentinel：测试前向 `.md` 与
`.markdown` 的 `OpenWithProgids` 注入唯一的第三方测试 ProgID，分别在安装后、卸载后核对它
仍存在，最后恢复精确基线。2026-08-29 对 0.1.3 草稿安装包实跑通过。该证据证明安装器保留
其他 Open With 候选；它没有把 sentinel 设置为真实默认应用，也没有创建全新 Windows 用户，
因此不能据此把 F1 的另外两种起始状态判为通过。

## 4. 其他未通过项的处置

- **E2**：现有状态机已覆盖“保存 A 时编辑 B、重复保存串行化、watcher 回声与离开保护”；
  第一轮没有缺陷证据，因此没有盲改保存实现。随后在 0.1.3 草稿发布版的真 WebView2 与真
  Rust IPC 上用双闸门稳定制造在途保存窗口，结果通过，详见 §6。
- **E5**：现有 composition gate 覆盖保存、模式、watcher、导航和退出。后续可补 host 边界的
  Chromium 集成测试，但真实微软拼音仍保持未执行。
- **F1/F2/F3**：分别需要不同用户/默认程序、干净 Win10、启用长路径的机器。F1 已增加
  第三方 Open With sentinel 回归；F3 已实现阻塞式 `windows-long-path` CI job，但必须等
  下一次远端运行成功后才能改判；F2 仍只能由对应干净环境给出结论。
- **H**：边界夹取、窄窗和正文居中已有自动化与真机证据；正文重叠是自由拖放的既定结果，
  若要禁止必须另立规格。

## 5. 验证与完成条件

必须满足：

- 定向 Windows installer/version 测试通过；
- 根 `npm test` 与 `npm run typecheck` 通过；
- 本机原始 Release 的 `/S` 卸载通过并有精确注册表/快捷方式证据；
- UI 卸载走到进程退出后的复测结果写回 M6 清单与 Windows 报告；
- `git diff --check` 通过；
- 未改变 UserChoice、其他应用 OpenWith 项或模式控件既定语义。

只有 UI 与静默两条卸载路径都通过，A4 才能从失败改为通过；环境未执行项继续按手册保持
“未执行”。

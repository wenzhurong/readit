## C6 — 外部链接交系统浏览器

SPEC §11.2：外部 `http(s)` **交系统浏览器**。

### ⚠️ 这个任务的重点不是"打开链接"，是"决定什么不打开"

`classifyHref()` 的 `'external'` **比"可以安全交给操作系统"宽得多**：
`packages/element/src/navigate.ts:23` 的判据是「有一个长度 ≥ 2 的 scheme」，
所以 `javascript:`、`file:`、`vscode:`、`smb:` 全部归为 `'external'`。

而壳打开的是**用户双击的任意本地 Markdown 文件**——内容不可信。
把 `'external'` 直接喂给系统 opener，等于让一份文档决定在用户机器上打开什么。

**要求**：壳自己维护一个**允许清单**，不要复用 `classifyHref` 的分类当授权判据。
建议只放行 `http:` / `https:`（`mailto:` 由你判断并写明理由）。**其余一律拒绝并可见地告知**
——静默吞掉一次点击，用户会以为是程序坏了。

**必须有的负向测试**（逐条，不许合并成一条）：
`javascript:alert(1)`、`file:///etc/passwd`、`data:text/html,...`、
`vscode://`、以及一个 scheme 大小写混写的变体（`JavaScript:`）。
断言：**不调用 opener，且有可见反馈**。

再加一条：**验证这些负向断言真的会红**——临时把允许清单换成"全放行"，
看它们变红，再改回来。

### 实现落点

Tauri 2 的官方做法是 `tauri-plugin-opener`（Cargo 依赖**钉死版本**，
与既有的 `notify = "=8.2.0"` 等一致，不许 `^`）。两条路径任选，写明理由：

- **JS 侧拦截**：在壳里捕获点击 / `onNavigate` 之外的外链激活，走一个 Rust 命令。
- **Rust 侧 `on_navigation`**：拦住 webview 自身的导航请求。

**注意 `target="_blank"`**：element 已经给外链加了它（那是 GitHub 形状，**不要为了
方便就去掉**——`navigate.ts` 那段有语料保真的理由）。在 Tauri webview 里
`target="_blank"` 的默认行为要**实测**清楚（可能开新 webview 窗口、可能什么都不做），
不要照浏览器的直觉假设。**报告里写你实测到的是什么。**

### 其余要覆盖的

- 外链点击后**当前文档不被导航走**（webview 不能跳出去）。
- `./other.md` 与 `#slug` 的既有行为不受影响——这两类**不归壳管**
  （`#slug` 由元素自己搭桥，相对路径走元素历史栈，见 SPEC §11.2）。
  加一条回归断言钉住"C6 没有顺手把它们也拦了"。

## C7 — Cmd+F 唤起内置查找栏

SPEC §11.3 点名这是 **v1 的实际阻塞项**：
**Tauri/WKWebView 在 macOS 上压根没有查找 UI**（tauri#9385，2024-04 开至今 needs-triage），
按 Cmd+F 什么都不会发生，**没人会替我们修**。

好消息是查找 UI 已经在 element 里了：`mount().find()` 不传 query 就"打开并聚焦内置查找栏"。
**C7 主要是把 Cmd+F 接到它上面**，不要在壳里重造一个查找 UI。

### 实现落点：两条路，我倾向原生菜单

- **原生菜单项 + accelerator**（macOS 的 Edit 菜单里出现 "Find…" ⌘F）。
  更符合 macOS 习惯，且不依赖 webview 是否拿到焦点。
- **JS `keydown` 监听**。简单，但焦点在编辑器 / 查找输入框 / 无焦点时行为要各自处理。

**选哪条你定，但要写明理由，并把没选的那条的代价写出来。**

### 要处理的边界（逐条测）

1. **`source` / `split` 模式**：焦点在 CodeMirror 里时按 Cmd+F 会怎样？
   CodeMirror 可能有自己的搜索绑定。**实测它，然后决定谁赢**——
   SPEC §11.3 第 7 点已经定了：源码模式必须查**文档模型**而非 DOM
   （虚拟化会漏掉屏外行），而 `mount().find()` 已经走的是文档模型
   （`kernel.ts:243` 的 `panes.getValue()`）。所以**应当让我们的查找栏赢**，
   但要确认不会与 CodeMirror 的绑定打架。
2. **查找栏已打开时再按 Cmd+F**：应当重新聚焦并全选输入框内容（浏览器的通行行为），
   不是关掉它、也不是开第二个。
3. **Escape**：关闭查找栏、清掉高亮、焦点回到文档。
4. **多实例同页**：壳里只有一个实例，但 `mount()` 支持同页多个——
   Cmd+F 应当作用在**当前聚焦的那个**。若壳里不会出现多实例，**写明这个前提**，
   不要留一个未定义行为。

### 验证

Codex **能**验的：查找栏被打开/聚焦、状态与计数、Escape 行为、
源码模式走文档模型、与 CodeMirror 绑定的相互作用——这些在 Playwright 里可测
（壳的前端是普通 web 页面）。**照做，不要因为"这是壳的功能"就整体推给手工。**

Codex **不能**验的：真 macOS 应用里按下物理 Cmd+F、原生菜单项是否出现在 Edit 菜单。
那是手工清单第 3 项（**已存在，未勾选**）。**不要新建一份重复的清单**，
需要补充操作步骤就改那一份。

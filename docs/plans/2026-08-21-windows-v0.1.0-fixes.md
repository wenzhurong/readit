# Windows v0.1.0 真机缺陷修复规格（供 Codex 执行）

**日期**：2026-08-21　**基线**：`readit-v0.1.0` / `5086b73`

## 0. 性质与证据边界

这不是新功能。`v0.1.0` 的 GitHub Release、安装与自动化均成功，但 2026-08-20 在
Windows 11 `10.0.26200`、WebView2 `151.0.4129.93` 的真窗口验收中发现三条明确回归，
另有一条导航焦点缺口：

| 编号 | 真机现象 | 已取得的定位证据 |
|---|---|---|
| WRF-1 | `doc-a.md` 的四张相对图片全部损坏 | 同一文件的协议探针对照中，`readit://localhost/...` 失败，`http://readit.localhost/...` 成功 |
| WRF-2 | 已有窗口时再次执行安装后的 exe，第二进程退出但窗口不打开 `D:\...\x.md` | 壳显示「已阻止不受支持的外部链接：D:/...」；盘符被外链捕获器当成单字母 scheme |
| WRF-3 | 长文档查找到屏外命中后，查找栏随页面滚走，鼠标按钮不可达 | WebView2 中按钮坐标落在窗口上方数千像素；键盘循环仍工作 |
| WRF-4 | 文档内相对导航成功后，`Alt+Left` 即使点击普通正文也可能无响应 | 历史键监听挂在宿主上，但普通正文点击不会取得键盘焦点 |

**真 WebView2 现象是本规格的上位事实。** happy-dom、Playwright Chromium 或构建成功只能
作为更早、更便宜的回归门，不能推翻上述证据。修复完成后必须重新构建 Windows release，
用真 WebView2 复测，不能只报自动化为绿。

## 1. 范围与不变量

### 1.1 本轮范围

1. 修复 Windows 生产环境的本地图片、音频、视频与 poster 资源 URL。
2. 修复第二实例投递的 Windows 盘符路径被外链安全门误拦截。
3. 让桌面壳的查找栏在文档滚动期间保持在窗口视口内且可操作。
4. 让用户点击普通正文后，组件历史快捷键能可靠取得焦点并处理前进/后退。
5. 为四条路径补能稳定复现旧实现失败的自动化断言，并在新 Windows release 上复测。

### 1.2 不变量

- 本地资源仍只能相对当前文档目录读取；`..`、盘符注入、UNC、控制字符与解码后斜杠的
  现有拒绝规则不放宽。
- 外部链接仍只允许 `http:` / `https:` 交给系统浏览器。`javascript:`、`data:`、
  `file:`、`mailto:`、自定义多字母 scheme 与协议相对 URL 仍须可见地阻止。
- Windows 盘符只是本地文档路径，不授予 WebView 任意文件读取能力；最终打开仍由 Rust
  `open_document` 的 Markdown 类型、规范化与路径守卫裁决。
- 查找计数、正反循环、Custom Highlight/`mark` 降级、源码模型搜索和 Escape 清理语义不变。
- 可复用元素不能因此在普通嵌入页面里全局劫持快捷键或把查找 UI 固定到整个页面视口。
- 不改安装器的「只加入打开方式、不抢默认程序」策略；不顺手处理性能预算或代码签名。

## 2. 已裁决语义

### WRF-1 — 资源 origin 必须按运行平台生成

Tauri 自定义协议在 Windows WebView2 的生产 origin 是 `http://readit.localhost/`；macOS/WKWebView
继续使用 `readit://localhost/`。CSP 保持两者都允许，但 **CSP 允许某个 origin 不等于 DOM 中
使用另一个 origin 也会被引擎自动改写**。

要求：

- 资源 URL 的平台选择集中在一个纯函数中，输入可在测试里显式注入；不得把 Windows 判断
  散落到每个属性重写分支。
- Windows 下相对资源生成 `http://readit.localhost/<encoded path>`；其他平台保持
  `readit://localhost/<encoded path>`。
- 查询串、fragment、空格/中文/既有百分号转义的现有编码语义不变，不做失败后双协议重试。
- `img[src]`、`source[src]`、`audio[src]`、`video[src]`、`video[poster]` 以及异步新增节点
  使用同一个已裁决的 base。

验收：单元测试覆盖两种平台 base；Windows release 打开 `doc-a.md`，蓝、红、两张绿色图片
全部显示，协议探针中的 Windows mapped origin 与 authored relative 显示一致。

### WRF-2 — 单字母冒号前缀不是外链候选

元素层 `classifyHref` 已把真实 scheme 的最小长度定为 2，从而把 `C:` / `D:` 摘出外链。
壳的 capture 安全门必须使用同一条分类边界：

- `C:/docs/a.md`、`D:\docs\a.md` 与扩展路径经 `normalizeDocumentPath` 得到的盘符路径不得被
  `connectExternalLinks` 截获，事件继续交给元素历史/导航合同。
- 两个字母及以上的 scheme 继续进入外链安全门；其中仍仅 http(s) 放行。
- 新增一条组合级测试：先连接 `connectExternalLinks`，再调用 `routeDocumentOpen` 投递盘符路径。
  测试必须断言没有外链反馈，并且元素侧 click/navigation 处理器确实收到规范化路径。

验收：已有窗口打开 `doc-a.md` 后，第二次执行安装后的 exe 并传绝对 `doc-b.markdown`；
第二进程正常退出、进程总数仍为 1、现有窗口标题和正文切换到 doc-b，且历史中保留 doc-a。

### WRF-3 — 桌面壳查找栏固定于窗口，元素默认仍受宿主约束

通用元素当前的绝对定位默认值保留，避免嵌入方的查找栏逃出组件边界。元素通过一个带默认值的
CSS 自定义属性允许宿主裁决定位方式；桌面壳显式选择 `fixed`：

```css
.readit-find-ui-host {
  position: var(--readit-find-position, absolute);
}

#reader {
  --readit-find-position: fixed;
}
```

要求：

- 桌面壳中查找栏打开后始终位于窗口右上安全边距内；当前命中滚动到任意位置都不能改变其
  视口坐标或使按钮不可点击。
- 再按 `Ctrl+F` 必须让已存在的输入框回到视口、聚焦并全选；不得创建第二个栏。
- 默认嵌入行为仍为 `absolute`，不新增 JavaScript 公共 API，也不把壳判断写进 `@readit/find`。
- 至少一条真浏览器断言把页面滚到长文档底部，检查查找栏矩形仍在 viewport 内并点击
  Previous/Next 按钮验证可操作性。

### WRF-4 — 普通正文交互建立组件内导航焦点

元素仍只在自己的宿主范围处理历史键，不在 `window`/`document` 上全局监听。为导航控制器提供
已有的 `.readit-root[tabindex=-1]` 作为 focus target：

- 指针按下发生在普通、不可交互正文上时，程序化聚焦 root，且使用 `preventScroll`。
- 链接、按钮、输入框、textarea、select、`contenteditable` 与显式可 Tab 元素不被抢焦点。
- 焦点进入 root 后，`Alt+Left/Right` 与 macOS `Meta+[/]` 继续走既有历史栈；无可用历史时
  不阻止系统默认行为。
- 查找栏与 CodeMirror 的焦点恢复语义不能回归。

验收：真浏览器测试点击普通段落后按平台历史键，观察 `onNavigate` 回到上一文档；Windows
release 重复 doc-a → doc-b → 点击正文 → `Alt+Left`，应返回 doc-a。

## 3. 实施顺序与测试门

1. **规格先行**：本文件落盘后才允许改生产代码。
2. **先红**：分别加入 WRF-1～4 的定向断言，在旧实现上确认失败原因与真机现象一致。
3. **最小实现**：资源平台 base、单字母 scheme 边界、查找定位变量、正文焦点桥接分别落在
   现有模块内；`main.ts` 只做平台/壳接线。
4. **定向绿**：`shell`、`@readit/find`、`@readit/element` 单元测试及相关浏览器 spec。
5. **完整绿**：根目录 `npm test`、typecheck/build、Rust test/clippy；不得用删测试换绿。
6. **真机复测**：构建未签名 Windows release，按 §2 四项操作；记录 WebView2 版本、包哈希、
   通过/失败与仍未覆盖的边界。

| 项 | 原因 |
|---|---|
| 性能优化 | 本轮已记录 Working Set，但项目没有预算裁决；不能把缺陷修复扩张成无边界优化 |

## 2. 剩余项（按优先级）

### A. 安装器全流程　★最高优先

**为什么排第一**：这是第 1 项只能记「部分」的原因，而且**从来没有人做过**——上一轮是直接
跑 release exe，不是装出来的。安装器涉及注册表、文件关联、卸载，是自动化完全够不到的一层。

- [ ] **A1 全新安装。** 在没装过 readit 的状态下装一次。
      **期望**：装完不自动成为 `.md` 默认程序（反劫持，设计如此，不是缺陷）。
- [ ] **A2 从资源管理器双击 `.md`。** 先用「打开方式」选一次 readit。
      **期望**：文档在 readit 中打开；相对图片显示正常。
      记：三种起始状态的行为差异见 runbook §3.1，照那里做。
- [ ] **A3 覆盖安装。** 不卸载，直接再装一次同版本或装 0.1.0 覆盖。
      **期望**：不残留两份、快捷方式不重复、关联不丢失。
- [ ] **A4 卸载。** 从「应用和功能」卸载。
      **期望**：程序目录清空；文件关联条目移除；不残留孤儿注册表项导致下次安装异常。
      **卸载后请重装 0.1.1 再继续后面的项。**

### B. 第 3 项 · 查找矩阵补齐

上一轮只验了「栏固定在视口 + 按钮可点」这条缺陷路径。剩下的是常规矩阵，照
runbook §3 项的步骤做，重点在这三条：

- [ ] **B1 `Shift+Enter` 反向循环**，计数正确、能从第 1 个绕到最后一个。
- [ ] **B2 `Escape`** 关闭查找栏、清除高亮、焦点回到文档。
- [ ] **B3 源码模式下的查找**（切到 Source 再 `Ctrl+F`）行为与阅读模式一致。

### C. 第 4 项 · 原子保存文件监听

照 runbook「第 4 项」的两段命令做（① 临时文件 + rename，② 普通原地写入）。

- [ ] **C1** 外部原子替换后，界面在约 80ms 沉降窗口后更新为新内容。
- [ ] **C2** 普通原地写入同样能被观察到。
- [ ] **C3** 已知边界：非原子写入在沉降窗口之外仍可能读到中间态（D2-29），**这是已记录的
      债务，不是本轮新缺陷**——观察到就照实记，别当成回归。

### D. 第 5 项 · 真 WebView2 里的 Mermaid

照 runbook「第 5 项」。这一项在 macOS 上也只在 26.5.2 上过、下限未验，所以 Windows
这边的数据是新增证据。

- [ ] **D1** 三张图都渲出 SVG，不是错误态、不是原始源码。
- [ ] **D2** 长标签**没有被节点框裁掉**（这是 macOS 那轮修过的缺陷，Windows 要复看）。
- [ ] **D3** 语法错误的那张显示具名错误态，不抛未捕获异常。
- [ ] 注意 runbook §4.4：第 3 张图 H2 节点整体半透明是作者 `classDef` 的意图，
      **要看的是标签在不在自己的框里**。

### E. 第 7 项 · 编辑、保存、冲突与退出保护　★runbook 里没有，本节补齐

Windows 与 macOS 有三处**结构性差异**，先知道再测：

1. **没有应用菜单。** 模式切换与保存走 `Ctrl+1/2/3` 与 `Ctrl+S`（`edit-shortcuts.ts`，
   只在 Windows 生效）。macOS 那边是原生菜单项。
2. **退出路径不同。** macOS 上 ⌘Q 曾绕过退出保护（预定义 Quit 接 Cocoa `terminate:`），
   **那条缺陷在 Windows 上不存在**——Windows 没有应用菜单，退出走的是窗口关闭
   （`CloseRequested`），一直是被守住的。别去找一个不存在的 bug。
3. **行尾。** Windows 上的文档常见 CRLF，而 CRLF 保真是 0.1.1 才修的，这一项在
   Windows 上尤其值得认真测。

- [ ] **E1 模式入口与基本保存。** 打开一份**含中文、CRLF 与尾随换行**的 `.md`；用
      `Ctrl+1/2/3` 在 Reading / Source / Split 之间切；编辑正文后 `Ctrl+S`。
      **期望**：只有三个模式没有 `plain`；编辑后**标题栏出现 `●` 且右上角显示「未保存」**；
      保存后两者都消失。
      **然后用十六进制工具核对磁盘字节**（PowerShell：`Format-Hex -Path x.md | Select -First 5`）：
      **CRLF、非 ASCII、尾随换行必须逐字节原样保留**。这是 0.1.1 的核心修复之一。
- [ ] **E2 保存时序。** 改成 A，按下保存后立刻继续改成 B；等保存完成后再保存一次。
      **期望**：第一次只把 A 写盘、界面仍把 B 标脏；不会因 A 的 watcher 回声弹出冲突；
      第二次保存后磁盘为 B 且清脏。
- [ ] **E3 外部变更冲突。** 本地有未保存修改时，从另一个编辑器原子替换同一文件。
      **期望**：本地输入不被覆盖；出现「使用磁盘版本 / 保留我的修改」提示；
      选「保留」后仍标脏且下次保存可覆盖磁盘；选「使用磁盘版本」应用磁盘内容并清脏。
- [ ] **E4 关闭与退出保护。** 脏状态下点窗口的 ×，以及 `Alt+F4`。
      **期望**：都被拦下并给出「保存 / 放弃 / 取消」三个动作；选「取消」留在原文档且未写盘；
      选「保存并关闭」写盘后关闭；选「放弃并关闭」关闭且磁盘原样。
- [ ] **E5 中文输入法。** 用**真实系统输入法**（微软拼音）在 Source 中输入一段中文，
      在**预编辑串尚未提交时**分别触发保存、模式切换、外部文件变化。
      **期望**：动作都等组合提交后再继续；刚提交的中文不被静默覆盖。
      ⚠️ **必须使用真实输入法**——合成事件与 CDP 都不能替代这条结论。

## 3. 已知会被误当成缺陷的东西（补充 runbook §4）

runbook §4 那五条仍然有效。这一轮新增三条：

6. **SmartScreen 拦截首次运行** —— 未做代码签名的必然结果，已裁决，不是缺陷。
7. **输入法组合期间快捷键"没反应"** —— 2026-08-21 在 macOS 上实测到：中文输入法组合
   进行中时，退出快捷键会被**输入法本身吞掉、根本到不了应用**。Windows 上同理。
   这与「壳把动作推迟到 `compositionend`」现象一模一样（都是"按了没反应"），但成因
   完全不同。**做 E5 之前必须先把两者分开**，否则很容易得出一条假通过。
   区分方法：先按 `Esc` 结束组合，再按同一个快捷键——若这次有反应，那就是输入法吞的。
8. **标题栏不显示文件名与 `●`** —— 如果出现，检查是不是装的旧版本。这是 0.1.1 修的
   （`core:window:allow-set-title` 权限缺失会让它**静默失效、界面不报任何错**）。

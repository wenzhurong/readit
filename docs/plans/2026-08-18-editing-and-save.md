## 1. 六条已裁决的语义（不要重新讨论）

控制端 2026-08-18 与用户共同裁决。**这些是前提，不是选项。**

### 裁决 1 — 保存写回「Rust 已持有的当前文档」，命令**不接受路径参数**

`open_document(path)` 收任意路径，读是合理的（用户自己选的文件）。**写不行。**
`AppState.resources.current` 已经存着规范化后的当前文档路径，`save_document` 只写那一份。

这样「webview 能写任意文件」这一整类风险直接不存在，不用靠消毒器兜底。
**与 `external.rs` 同一条纪律：不要复用渲染端的分类当授权判据，壳自己维护权威。**

### 裁决 2 — 用原子写（临时文件 + rename）

台账 D2-29 自己论证过：POSIX 没办法让读者知道写者写完了，**原子保存存在的理由正是
消除这个竞态**。readit 若不原子地写自己的文档，就是在制造一个自己文档里刚写明
「不可修」的竞态。

### 裁决 3 — 自写抑制用**内容比对**，不用时间窗

保存必然触发自己的 watcher。**不许用「刚写完 N 毫秒内忽略」**——那是又一个猜出来的
常数，并发下必错，且这个项目已经因猜数字栽过两次。

做法：重载拿到内容后，**若与编辑器当前值逐字节相同就什么都不做**（不调 `setValue`）。
确定、无时序假设，还顺带覆盖「外部工具写了相同内容」。

### 裁决 4 — 外部变更遇上未保存修改：**不自动覆盖，可见地提示**

今天是无条件 `setValue`，脏内容直接没。只读时正确，可编辑后是数据丢失路径。

有未保存修改时**不自动应用**外部变更，显示提示让用户选「用磁盘版本」或「保留我的修改」。
依据是项目自己的原则：**降级必须可见**（SPEC §12，`data-readit-pending` 是先例）。
**静默丢用户输入比任何降级都糟。**

### 裁决 5 — 手动保存（`Cmd/Ctrl+S`），有脏状态

不做自动保存。语义最清楚、最可预期，也最容易验收（「按了才写盘」是可断言的）。

### 裁决 6 — 壳暴露 `source` + `split`，原生菜单 + 快捷键；`plain` 不进壳

`plain` 是给「想能改字但不想付 176 KB」的**嵌入方**的档，桌面壳里 CodeMirror 已经
打包进去了，多暴露一个档只是多一份要验收的行为。

### 裁决 7 — 脏状态由**宿主**维护，元素不加 `isDirty()`

元素不知道「已保存」是什么意思——那是宿主的概念。元素只负责在用户编辑时发
`onChange(value)`，宿主自己比对。**这样公开 API 只加一个回调，不加状态。**

## 2. 任务

### E1 — 元素层：`onChange` 编辑通路

`MountOptions` 加 `onChange: ((value: string) => void) | null`，默认 `null`。
接线：`panes.ts` 的编辑器 `onChange` → `PanesOptions.onChange`（照 `onPending` /
`onPainted` 的既有形状）→ `kernel.ts` 调 `opts.onChange`。

⚠️ **本任务最要紧的一条正确性要求**：

> **`onChange` 只能因「用户编辑」而触发，绝不能因宿主调 `setValue()` 而触发。**

否则一个「收到 onChange 就保存」的宿主会自己把自己转成死循环。**这条要有专门的断言，
并且要注入缺陷验证它会红。**

同样不该触发的：`setMode()` 切模式、`setTheme()`、外部导航。

**验收**：
- 用户编辑 → 触发，带最新全文
- `setValue()` → **不触发**
- `setMode()` 在四个模式间来回切 → **不触发**
- 默认 `null` 时一切照旧（`DEFAULT_MOUNT_OPTIONS` 的守卫会逼你显式登记，见
  `packages/element/test/mount.test.ts`）
- 真浏览器合同：`browser/editor/` 下补一条，两个引擎都要过

---

### E2 — 壳：模式入口

**macOS**：原生菜单栏加 View 子菜单（Reading / Source / Split），带 accelerator。
与 C7 当初选原生菜单同一理由：更贴 macOS 习惯，且不依赖 webview 是否拿到焦点。

**Windows**：没有菜单栏，用 window 捕获键盘监听——照 `find-shortcut.ts` 的既有形状
（`connectFindShortcut` 那条 window capture 监听）。**W3 已经全局禁用了浏览器加速键，
不会与 WebView2 相争。**

菜单/快捷键事件 → 前端 → `handle.setMode()`。

**要处理的边界**：
- 模式是**元素状态**，换文档走 `setValue()` 不重挂，所以模式会跨文档保持。这是合理的，
  但要**写明**这个行为，别让它成为未定义。
- 切到 `source`/`split` 时 CodeMirror 才第一次动态加载（P1 的懒加载边界），首次切换有
  延迟。**确认它不会看起来像卡死**——需要的话给一个可见的加载态。
- 当前模式要在菜单里可见（选中态），否则用户不知道自己在哪一档。

---

### E3 — Rust：`save_document` 命令

**签名不带路径**（裁决 1）。写回 `AppState.resources.current`。

```
save_document(content: String, state) -> Result<(), String>
```

**必须做的**：
- 原子写：同目录临时文件 + `rename`（裁决 2）。**同目录**——跨设备 rename 会失败。
- 失败时清理临时文件，不留垃圾
- 没有已打开文档时明确报错，不要静默成功
- 目标仍须通过 `is_markdown`（与 `open_document` 同一守卫）
- 写入后**同步更新自己对内容的记账**，供裁决 3 的内容比对使用（或者把比对完全放前端，
  两种都可以，**写明你选了哪种以及为什么**）

**验收**：
- 写入字节与传入内容完全一致（含 CRLF / 尾随换行 / 非 ASCII）
- rename 之后 inode 变了、内容对（M6 第 4 项已经证明我们的 watcher 认得这个）
- 无文档时报错
- 临时文件在成功与失败两条路径上都不残留
- **权限被拒时**（只读文件、只读目录）错误可读，不是 panic

### E4 — 壳：保存状态机（**独立模块，不许写进 main.ts**）

新建 `shell/src/save-state.ts`（名字你定），`main.ts` 只接线。理由见 §0.5。

**它要管的状态与转移**：

| 事件 | 行为 |
|---|---|
| 元素 `onChange` | 标脏；记下当前值 |
| `Cmd/Ctrl+S` | 调 `save_document`；成功 → 清脏；失败 → 可见报错，**保持脏** |
| 文件监听触发、**不脏** | 拿到磁盘内容；**与当前值逐字节比对**（裁决 3），相同则什么都不做，不同则 `setValue` |
| 文件监听触发、**脏** | **不自动应用**（裁决 4），交给 E5 提示 |
| 导航到别的文档时脏 | 先提示，不要直接走掉 |
| 关窗时脏 | 先提示 |

**验收**：这个模块要能在**不启动应用**的情况下被单测覆盖——纯状态机，依赖用参数注入
（照 `createWatchedDocumentReloader(currentPath, reload, reportError, delayMs)` 的形状）。
**每条转移一条断言，每条都要证明会红。**

### E5 — 冲突提示与脏标记的可见性

- **脏标记**：窗口标题加约定记号（macOS 的 `documentEdited` 或标题前缀），或状态区可见提示
- **冲突提示**：两个动作——「用磁盘版本」（丢弃本地改动）与「保留我的修改」（忽略这次外部变更）

依据是 SPEC §12「降级必须可见」，元素侧的 `data-readit-pending` 是既有先例。

## 3. 已知陷阱（具名、有出处）

1. **`onChange` 因 `setValue` 触发 = 死循环**。E1 的头号要求，见上。

2. **保存会触发我们自己的 watcher**。裁决 3 用内容比对解决。**不要用时间窗。**

3. **组合期的 `setValue()` 会静默丢掉刚提交的输入法文本**（SPEC §9.4，用户
   2026-08-13 裁决「维持现状」）。**那条裁决的前提是没人能编辑，现在前提变了。**
   裁决 4 挡住了「脏 + 外部变更」这条路径，但**不脏时的外部变更仍会 `setValue`**，
   仍可能落在组合中间。**在报告里写明你怎么处理这一段，或者明确它仍是已知边界。**

4. **`GAP-IME-WEBKIT`**：WKWebView 没有等价于 CDP `Input.imeSetComposition` 的入口，
   四条真机组合测试在 WebKit 上整体跳过——**其中一条恰好是「组合期间到达的外部
   `setValue` 被推迟」**，也就是上一条的守卫在 macOS 的出货引擎上没有覆盖。
   **不要因为它在 Chromium 上绿就当它在 macOS 上成立。**

5. **临时文件必须与目标同目录**。跨设备/跨卷 `rename` 会失败，而 `/tmp` 与用户文档
   经常不在同一个卷上。

6. **模式跨文档保持**。换文档走 `setValue()` 不重挂，模式是元素状态。这是既定行为
   （它也是前进/后退历史栈能工作的原因），**不要为了"每次都回到阅读模式"去重挂**。

7. **`plain` 档不进壳**（裁决 6），但 `getValue()` 在它上面本来就能用——
   **不要把保存做成模式相关的**，它只该依赖「当前值」。
